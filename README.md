## What is in this repository?
This is a balanced reorganisation of the original semester DBMS archive. The source contained 74 SQL files. Instead of keeping dozens of tiny one-query files, related questions are grouped into **topic-wise practical files**. The original question labels and source filenames are noted inside each section so the work remains traceable.

The repository retains the range of practical work: table creation and constraints, keys, referential actions, SELECT queries, string functions, aggregates, filtering, GROUP BY, joins, online lab exercises, customer/order tables and subqueries. Three exact/repeated query files were consolidated; genuinely different questions remain.

## How to use the grouped SQL files
1. Open a file and read the `Original practical:` heading above each section.
2. Execute one section at a time in MySQL Workbench or the MySQL command-line client.
3. Create/select the required database and tables before running dependent queries.
4. Some questions reuse table names with different structures. Do not blindly run every section in one batch; follow the question boundaries.
5. For the subquery practicals, create the employee sample table using the earlier setup section before running dependent questions.

## Validation notes
- These files target MySQL. Some syntax (such as `AUTO_INCREMENT`, `REGEXP`, `YEAR`, `ENGINE=InnoDB` and window functions) is MySQL-specific.
- MySQL does not directly implement `FULL OUTER JOIN`; the practical demonstrates an equivalent using left/right join results where applicable.
- The composite foreign key example needs a parent `departments` table with a UNIQUE or PRIMARY KEY on `(department_id, manager_id)`.
- One original date/check constraint had invalid syntax and was corrected to use a valid decimal declaration and a meaningful date-order check. The correction is documented in the duplicate/correction report.
- Pasted MySQL prompts and terminal result tables have been cleaned from transcript-based files. Results should be generated by executing the queries.
- No live MySQL server was available for execution testing in this environment. The SQL was organised and statically reviewed, but runtime success is not claimed.
